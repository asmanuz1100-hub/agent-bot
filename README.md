# ASMAN Агент — тест версия 0.2

Python 3.11+ стандарт кутубхонаси билан ишлайди. Ҳозирча серверга жойланмаган ва Telegramда ҳақиқий бот билан синов ўтказилмаган.

## Ишга тушириш

1. Telegramда @BotFather орқали /newbot билан бот очинг.
2. BOT_TOKEN ва ўз Telegram рақамли IDнгизни ADMIN_IDS муҳит ўзгарувчисига киритинг. Токенни кодга ёки GitHubга қўшманг.
3. Доимий дискда DB_PATH белгиланг. Битта жараён ишлатинг. Windowsда Python 3.11+ ва зарур бўлса `pip install tzdata` керак.
4. `python bot.py` ни ишга туширинг. Long polling: бот учун webhook ўрнатилмаган бўлиши керак.
5. Админ ботга /start юборади. Ходимлар ҳам /start юборади; уларга Telegram ID кўрсатилади.
6. Админ «Ходим» орқали agent ва cashier вазифаларини беради. Битта Telegram аккаунт битта вазифада; админ ўзини агент қилиб қўшмайди.

Linux / macOS мисоли:

```bash
export BOT_TOKEN='BOTFATHER_TOKEN'
export ADMIN_IDS='YOUR_NUMERIC_TELEGRAM_ID'
export DB_PATH='/persistent/asman/asman.sqlite3'
python bot.py
```

## Агент жараёни

- «Ишни бошлаш» → Telegram 📎 → Локация → жонли локация улашиш. Муддат тугаса қайта улашиш керак.
- «Мижоз қўшиш» → дўкон расми ёки скриншот → исм, телефон, манзил → оддий дўкон локацияси → тасдиқлаш.
- Расмни мижоз қўшиш жараёнида юбориш мумкин. Расмдан товар миқдори автомат ҳисобга киритилмайди.
- «Товар бериш»: мижоз → қадоқ → дона/блок → миқдор → тасдиқлаш.
- Фақат Грунтовка 7/1: 1 кг, 3 кг, 5 кг. Ҳаммасида 1 блок = 4 дона.
- «Сотилган товар»: амалда сотилган миқдор ва шу миқдорнинг умумий суммасини қўлда киритиш. Нарх ҳали белгиланмагани учун бот тахмин қилмайди.
- «Пул олиш»: мижоздан ҳақиқатан олинган нақд пул. Товар сотилиши ва пул олиниши алоҳида ҳаракатлар.
- «Кассага топшириш»: сумма кутиш ҳолатига ўтади; кассир «Касса»да /accept ID ёки /reject ID билан қарор қилади.
- «Товар қайтариш»: сотилмаган товар дўкондан агентга қайтади.
- «Ташриф / таклиф»: суҳбат, бозор нархлари ва таклифлар матни қайд қилинади.
- «Ишни тугатиш»: бот янги нуқталарни сақламайди. Telegramдаги улашишни агент ўзи ўчиради.

## Админ

- «Агентга товар»: агент қолдиғига кирим; бу тестда заводнинг умумий тайёр маҳсулот омбори ҳисобланмайди.
- «Агентлар»: агентнинг охирги сменаси, иш бошлаш/тугатиш, охирги нуқтанинг харита ҳаволаси, тахминий масофа, тўхташлар, маълумотсиз вақтлар, ташриф сони ва CSV маршрут.
- «Мижозлар»: агентлар бўйича реализациядаги қолдиқ, сотилган товар суммаси минус қабул қилинган пул. Манфий баланс — аванс.
- «Умумий ҳисоб»: агент қолдиқлари, нақд пул ва охирги 30 та буюртма.
- Агент ҳаракат ҳисоботлари серверда ҳар сўровда role=admin бўйича текширилади. Кассир фақат пул топширишларини кўради.

## Расмни автомат ўқиш (ихтиёрий уланади)

`OPENAI_API_KEY` ва ихтиёрий `OCR_MODEL` (стандарт: `gpt-4.1-mini`) белгиланг. Расмдаги мижоз исми, телефон ва манзил OpenAI Responses API орқали ўқилади. Бу API алоҳида ҳисоб/тўлов талаб қилиши мумкин. Расм хизматга юборилади, `store=false` қўлланади; бу провайдернинг барча маълумот сақлаш қоидаларини бекор қилмайди.

Бот ҳар майдон учун ўқилган маълумотни таклиф қилади: «Ўқилганини олиш» ёки тўғрисини қўлда ёзиш. Якуний тасдиқсиз мижоз сақланмайди. API калитсиз ҳам бот ишлайди: расм бириктирилади, маълумотлар қўлда киритилади. Координаталар расмдан тахмин қилинмайди.

## Локация таҳлилининг чегаралари

- Фақат иш вақтидаги, агент ўзи улашган жонли локация қабул қилинади. Эски смена хабарининг таҳрирлари янги сменага кирмайди.
- 5 дақиқадан узоқ оралиқ маълумотсиз деб белгиланади. Узилган нуқталар ораси масофага қўшилмайди.
- 100 метрдан ёмон аниқлик ва 198 км/соатдан тез сакрашлар масофадан чиқарилади.
- 70 метр атрофида камида 5 дақиқа туриш тахминий тўхташ. Бу алгоритм ҳақиқий ташрифни исботламайди.
- Масофа нуқталар орасидаги чизиқлар бўйича, автомобиль йўли бўйича эмас. GPS хатоси масофани ошириши ёки камайтириши мумкин.
- Тўлиқ интерактив маршрут харитаси ҳали йўқ: охирги нуқта харита ҳаволаси ва CSV экспорт бор. Ҳисобот админ сўраганда янгиланади.

## Тест версиянинг қолган чегаралари

Буюртма — талаб қайди, омбор ва қарзга таъсир қилмайди; етказилишини буюртма билан автомат боғлаш ҳали йўқ. Маршрут вазифаларини олдиндан белгилаш, банк ўтказмалари, нарх справочниги, ишлаб чиқариш ҳисоби, ҳисобот PDF, Telegram орқали хатоларни сторно қилиш ва тўлиқ аудитор интерфейс кейинги босқичда. Жорий ёзувларни ўчириш/таҳрирлаш тугмаси йўқ. Тестда сунъий маълумотлардан фойдаланинг; ҳақиқий ишдан олдин захира нусха ва тиклаш тартибини созланг. Узоқ муддатли GPS архиви учун ўчириш сиёсати ҳали қўшилмаган.

Бир агентнинг мижозини бошқа агент ўзгартира олмайди. Бир хил телефон қайта рўйхатга олинмайди. Бот фақат шахсий чатда ишлайди.

SQLite операциялари транзакцияда. Telegram update ID такрорий ҳаракатлардан ҳимоя қилади. Telegram жавоби узилиб қолса, айрим матн хабарлари такрор кўриниши мумкин; тасдиқсиз ёки икки марта тасдиқлашдан баланс икки марта ўзгармайди.

## 0.2 — Акт сверка ва ҳафталик таҳлил

«Акт сверка» → мижоз → бошланиш / тугаш санаси → тасдиқлаш. Бот қисқа баланс ва чоп этиладиган HTML файл беради. Браузерда очиб Print → Save as PDF орқали PDF қилиш мумкин; бот ҳозир тўғридан-тўғри PDF яратмайди. Даврнинг икки чегара санаси ҳам Тошкент вақти бўйича киритилади. Бошланғич қолдиқ олдинги операциялардан ҳисобланади. Реализациядаги сотилмаган товар пул қарзидан алоҳида.

«Ҳафталик таҳлил» — бугун ва олдинги 6 календарь кун, сўров вақтигача. Агент ўзини, админ танланган агентни кўради. Алоҳида дўконлар сони, жами ташрифлар, ташриф кунлари, берилган/сотилган/қайтарилган товар, буюртма, пул ва жорий қолдиқлар чиқади. CSVда давр операциялари ҳам берилади. Бу сўров бўйича ҳисобот, автомат режали хабар эмас. Дўконга кирганда «Ташриф / таклиф»ни албатта қайд қилинг: товар бериш ёки мижоз қўшишнинг ўзи ташриф сонига кирмайди.

Кассир тасдиқлаган вақт энди алоҳида сақланади. 0.1дан қолган эски қабул ёзувларида тасдиқ вақти йўқ бўлса, ҳисобот аввалги топшириш санасидан фойдаланади.

## Render ва GitHubга тайёрлаш

`render.yaml` доим ишлайдиган `starter` worker ва 1 GB доимий диск конфигурациясидир. Бу ПУЛЛИК таклиф, ҳали қўлланмаган. Worker ва диск учун бепул тариф йўқ. Аниқ жорий харажатни Render Dashboardда кўриб тасдиқланг. Бепул web service + маҳаллий SQLite қўлланмасин: қайта ишга тушганда маълумот йўқолади. Бепул вариант учун алоҳида webhook/Postgres ечими талаб қилинади; жорий код унга мослаштирилмаган.

1. Алоҳида private GitHub репозиторийга ушбу файлларни жойланг. `.env`, `data/`, SQLite базаси ва токенларни жойламанг.
2. GitHub Actions 21 та тестни бажаради.
3. Renderда Blueprint орқали `render.yaml`ни танланг. BOT_TOKEN ва ADMIN_IDS қўйилади. OPENAI_API_KEY ихтиёрий.
4. Доимий диск /var/data, база /var/data/asman.sqlite3. Битта инстанс. SIGTERMда жорий амал тугалланиб тўхтайди.
5. Биринчи синов: админ /start → агент/кассир → агентга 12 дона → мижоз → 4 дона реализация → 2 дона сотув → тўлов → кассир қабул қилиш → акт сверка → ҳафталик ҳисобот.

Render CLI бу муҳитда мавжуд эмас; Blueprint Render CLI билан ҳали текширилмаган. Деплой ҳолати ҳақидаги ҳақиқий натижа алоҳида хабар қилинади.
